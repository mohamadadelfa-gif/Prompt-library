# Writing Workflow

## Purpose

The Writing Workflow is the textual-content branch of the Prompt Library.

It is responsible for:

- searching for textual source material
- source evaluation and provenance
- topic research
- article/document analysis
- extracting key ideas and terms
- content strategy
- outlining and structure
- drafting
- rewriting
- summarization
- explanation
- language-level adaptation
- tone and audience adaptation
- grammar and style revision
- fact/claim review
- captions, hooks, CTAs, alt text, scripts, and other text deliverables
- writing QC

It functions independently from the Design Workflow even when both branches contribute to the same final social-media asset.

## Core Pipeline

```text
CONTENT NEED / TOPIC
→ WRITING BRIEF
→ TEXTUAL RESEARCH STRATEGY
→ SOURCE SEARCH
→ SOURCE EVALUATION
→ DOCUMENT / ARTICLE ANALYSIS
→ IDEA + CLAIM EXTRACTION
→ AUDIENCE / LANGUAGE CONSTRAINTS
→ CONTENT STRUCTURE / OUTLINE
→ DRAFT
→ LANGUAGE + TONE ADAPTATION
→ FACT / PROVENANCE CHECK
→ WRITING QC
→ HUMAN CONTENT REVIEW
→ APPROVED WRITING OUTPUT
→ OPTIONAL DESIGN HANDOFF
```

## Research and Knowledge Behavior

The Writing Workflow may use shared research, project knowledge, tools, and external sources. It may also consult Design knowledge when textual decisions depend on visual context, such as:

- expected text length
- reading order
- platform constraints
- title length
- slide count
- text density
- caption versus on-canvas division

However, visual references must not be treated as factual textual sources unless they actually contain reliable textual evidence.

## Accessible Explanation Pattern

For complex source material, prefer:

```text
SOURCE
→ CORE IDEA
→ KEY TERMS
→ CLAIMS / EVIDENCE
→ COMPLEXITY ASSESSMENT
→ EXAMPLE / ANALOGY WHERE USEFUL
→ AUDIENCE-APPROPRIATE EXPLANATION
→ MEANING-PRESERVING SIMPLIFICATION
→ FACT CHECK
```

For English Beyond Language, the current approved rule is that public-facing content language should normally be approximately B1 while preserving the intellectual substance of the subject.

## Writing Handoff to Design

A Design Handoff should contain only approved text and explicit flexibility states.

Recommended fields:

```text
CONTENT_ID
VERSION
CONTENT_PURPOSE
AUDIENCE
LANGUAGE_LEVEL
TITLE_OR_HOOK
ON_CANVAS_COPY
SEMANTIC_HIERARCHY
LOCKED_WORDING
FLEXIBLE_WORDING
EMPHASIS_TERMS
CTA
CAPTION
ALT_TEXT_INTENT
SOURCE_REFERENCES
FACT_STATUS
UNRESOLVED_UNKNOWNS
HUMAN_APPROVAL_STATE
```

## Boundary Rule

```text
WRITING OWNS MEANING, LANGUAGE, CLAIMS, AND TEXTUAL STRUCTURE.
DESIGN MAY FORMAT APPROVED TEXT BUT MAY NOT SILENTLY REAUTHOR IT.
```

If visual constraints require a meaningful rewrite, return the request to Writing with the constraint instead of editing the meaning inside the Design branch.
