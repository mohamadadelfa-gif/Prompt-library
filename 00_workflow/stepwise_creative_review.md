# Stepwise Creative Review Protocol

## Purpose

Creative outputs must be reviewed incrementally. The system must not generate the entire production chain in one opaque step when a human is expected to guide the creative direction.

## Review Sequence

### CHECKPOINT 01 — Named Style Study

Review:

- style understanding
- source quality
- separation of fact / observation / interpretation
- emotional interpretation
- transferable principles

Decision:

`PASS | CONDITIONAL | BLOCKED`

Do not proceed to reference synthesis if the study is blocked.

### CHECKPOINT 02 — Reference Style Synthesis

Review:

- supplied reference fidelity
- formal language
- material behavior
- composition
- emotional effect
- communication effect
- non-transferable elements

Decision:

`PASS | CONDITIONAL | BLOCKED`

### CHECKPOINT 03 — Platform Translation

For Instagram, review:

- mobile readability
- platform dimensions
- content hierarchy
- slide roles
- reusable zones
- emotional fidelity
- originality

Decision:

`PASS | CONDITIONAL | BLOCKED`

### CHECKPOINT 04 — Template Candidate

Review the reusable template separately from the specific content instance.

Questions:

- Can a different post use this structure?
- Which elements are editable?
- Which elements are controlled?
- Which elements are locked?
- Does the template preserve the intended visual character?

Decision:

`APPROVE | REVISE | REJECT`

### CHECKPOINT 05 — Art Direction

Review the content-specific creative direction before generation.

Confirm:

- objective
- message
- hierarchy
- visual concept
- approved references
- template
- constraints

Decision:

`APPROVE | REVISE | REJECT`

### CHECKPOINT 06 — Generation Output

Review the generated visual against the approved art direction.

Do not modify the template automatically because an individual generation failed.

Decision:

`APPROVE | REVISE | REGENERATE`

### CHECKPOINT 07 — Human Revision

Preserve:

- original generation
- human revision
- approved result
- change description
- reason for change

Then determine whether the revision is:

- one-off correction
- project preference
- reusable template improvement
- style reference
- style rule

### CHECKPOINT 08 — Figma Implementation

Build the approved design as editable production layers.

Verify:

- exact content
- frame dimensions
- typography
- colors
- components
- variables
- editable/controlled/locked fields
- export settings

Decision:

`PASS | REVISE | BLOCKED`

### CHECKPOINT 09 — Final Content Package

Confirm the production package contains:

- approved visual
- caption
- CTA
- alt text
- publishing metadata
- approved template relationship
- style reference relationship
- Figma implementation
- provenance

Decision:

`APPROVE | REVISE | BLOCKED`

## Core Rule

A human may approve or revise one layer without automatically changing every related layer.

For example:

- Changing a caption does not automatically change the visual template.
- Changing one image does not automatically change the style rule.
- Improving a Figma layout does not automatically rewrite Art Direction.

Every change must be explicitly classified and routed.
