# English Beyond Language — Retrieval Map

## Purpose

Make EBL memory operational for both Writing and Design by retrieving only the authoritative memory required for the current task while never omitting mandatory project rules.

## Core Rule

```text
TASK
→ IDENTIFY WORKFLOW / ASSET / PLATFORM / ACTION
→ RETRIEVE REQUIRED MEMORY SET
→ CHECK CONFLICT / SUPERSESSION
→ EXECUTE
→ RUN APPLICABLE QC
```

Do not retrieve the entire project indiscriminately when a smaller authoritative set is sufficient. Do not omit mandatory project rules merely to save context.

---

# Writing Core — Always Retrieve for EBL Content Tasks

1. `EBL_memory_registry.json`
2. `EBL_project_memory.md`
3. `EBL_approved_project_rules.md`
4. `EBL_content_communication_rules.md`
5. `EBL_decision_log.md`
6. relevant content-specific decisions
7. relevant source/provenance records

Mandatory current content rules include:

- no elitist positioning;
- motivational, learner-centered social communication;
- no random/filler content;

- B1 language must not reduce the intellectual substance of the subject.

# Task Routing

## A. Textual Research / Article or Document Analysis

Retrieve:

- Writing Core;
- supplied source/document;
- relevant external research references;
- article/document explanation methodology when useful;
- project terminology and audience rules.

Required behavior:

```text
SOURCE
→ CLAIMS / KEY TERMS / EVIDENCE
→ COMPLEXITY / UNCERTAINTY
→ CONTENT RELEVANCE
→ SOURCE-BACKED SYNTHESIS
```

Do not draft public-facing copy before source understanding is sufficient.

---

## B. EBL Social Copy / Caption / CTA

Retrieve:

- Writing Core;
- content objective;
- platform/format constraints;
- approved source synthesis;
- applicable series/campaign rule.

Before approval check:

```text
PURPOSE
FACT / CLAIM SUPPORT
NON-ELITIST POSITIONING
REALISTIC MOTIVATION
B1 LANGUAGE FIT
MEANING PRESERVATION
CTA FIT
```

---

## C. A Line for Today

Retrieve:

- Writing Core;
- exact quotation/source information;
- series-specific approved template/content rules when available;
- Story platform constraints;
- exact Writing → Design handoff for production.

Required behavior:

- do not paraphrase an exact quote;
- verify author/work/date or mark unresolved;
- keep attribution traceable;
- do not invent contextual claims;
- keep supporting language concise and accessible;
- hand locked quote wording to Design.

---

## D. Logo Use / Logo Replacement

Retrieve:

- Design Core;
- `EBL_asset_registry.json`;
- `EBL_logo_application_rules.md`;
- `QC-LOGO-001_logo_application_qc.md`;
- `QC-EBL-001_project_master_qc.md`;
- approved source artwork being revised.

Required asset resolution:

```text
EBL-ASSET-LOGO-001
or explicitly approved child variant
```

If the canonical binary cannot be resolved, do **not** regenerate a substitute. State `CANONICAL_ASSET_UNRESOLVED` and use/request the verified supplied asset.

---

## E. Carousel / Feed Post Creation

Retrieve:

- Design Core;
- approved Writing handoff when meaningful text is present;
- content-specific decision record;
- `EBL_visual_examples.md`;
- `QC-EBL-001_project_master_qc.md`;
- Instagram visual/audience QC;
- chosen-logo rules if branding is present;
- approved Visual DNA / art-direction sources.

Design may format approved Writing but may not silently re-author it.

---

## F. Carousel Revision

Retrieve:

- all Carousel Creation memory;
- approved source slide/set;
- exact approved Writing version if text is affected;
- `human_feedback_style_learning.md`;
- relevant failure records;
- typography/logo QC if touched.

Execution rule:

```text
AUTHORIZED DELTA ONLY
→ PRESERVE UNRELATED APPROVED ELEMENTS
```

If a requested visual change requires a semantic rewrite, route through Design → Writing handoff.

---

## G. Typography Repair / Typography Refinement

Retrieve:

- Design Core;
- exact approved copy / Writing version;
- `QC-TYPE-001_typography_integrity_qc.md`;
- `typography_native_reconstruction.md`;

- relevant visual example/failure records.

Typography refinement may change presentation, not approved textual meaning.

---

## H. Instagram Story Creation

Retrieve:

- Writing Core when text/content is being created;
- Design Core for visual production;
- approved Writing handoff;
- `EBL_story_template_rules.md`;
- `EBL_asset_registry.json`;
- `EBL_visual_examples.md`;
- `QC-EBL-001_project_master_qc.md` Story gate;

Remember:

- 1080×1920 / 9:16;
- Story-native reading path;
- usable interaction/sticker zone;
- secondary branding;

- current exact Story-template composition remains a review candidate until human-approved.

## K. Heavy QC / Final Output

Retrieve:

- applicable Writing and Design cores;
- exact approved Writing and Design versions;
- cross-workflow handoff record;
- `QC-EBL-001_project_master_qc.md`;
- `QC-EBL-MEM-001_memory_compliance_qc.md`;
- platform export requirements;
- final candidate set.

Final package must preserve mutual Writing/Design traceability.

---

## L. Learning / Structuralization

Retrieve:

- current human learning instruction;
- applicable Writing/Design core;
- decision log;
- failure memory;
- examples;
- system promotion policy.

Classify the new learning:

```text
ONE_OFF
CONTENT_SPECIFIC
REUSABLE_EBL_PROJECT_RULE
CROSS_PROJECT_SYSTEM_RULE
```

Do not promote one-off wording, composition, or coordinates into durable rules without explicit approval.

---

# Conflict Resolution

When retrieved records disagree:

1. current explicit human instruction;
2. newest non-superseded approved EBL decision;
3. approved project memory/rule;
4. approved content communication rules;
5. canonical asset registry where assets are involved;
6. content-specific record;
7. approved example/reference;
8. external evidence;
9. model inference.

If two approved records remain genuinely incompatible, surface the conflict rather than silently choosing.
