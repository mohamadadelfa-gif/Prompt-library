# English Beyond Language — Visual Production Workflow

## Purpose

Provide the project-level execution workflow for English Beyond Language visual content.

This workflow connects:

- durable project memory;
- machine-readable memory/asset registries;
- human decision history;
- negative/failure memory;
- approved/rejected visual calibration;
- chosen logo identity;
- visual DNA / Klee-informed principles;
- semantic typography;
- feed/carousel/Story production;
- human-directed revision;
- memory-compliance QC;
- Creative AI Final Edit;
- Heavy QC;
- final master / platform derivative output;
- learning promotion.

## Governing Principle

```text
TASK
→ MEMORY ROUTING
→ CONTENT MEANING
→ PLATFORM FUNCTION
→ CREATIVE EXECUTION
→ HUMAN REVISION
→ MEMORY COMPLIANCE QC
→ PROJECT QC
→ FINAL AI CLOSED LOOP
→ HUMAN FINAL APPROVAL
→ OUTPUT
→ LEARNING / MEMORY UPDATE
```

# Phase 0 — Memory Routing / Source Lock

Before creating or revising an EBL visual, retrieve the core memory set:

1. `knowledge/project/EBL_memory_registry.json`
2. `knowledge/project/EBL_project_memory.md`
3. `knowledge/project/EBL_approved_project_rules.md`
4. `knowledge/project/EBL_decision_log.md`
5. `knowledge/project/EBL_failure_memory.md`
6. `knowledge/project/EBL_retrieval_map.md`
7. `qc/QC-EBL-MEM-001_memory_compliance_qc.md`

Then follow `EBL_retrieval_map.md` to retrieve only the additional task-specific memory required.

Examples:

- logo/identity → `EBL_asset_registry.json` + logo rules/QC;
- typography repair → exact copy decision + typography reconstruction/QC;
- Story → Story rules + Story candidate/asset state;
- revision → approved source + human revision protocol + relevant failures;
- final AI → visual examples + failure memory + closed-loop finalization.

## Unknown discipline

Do not invent:

- canonical file paths;
- hashes;
- dimensions;
- variant approval;
- provenance.

Use `UNKNOWN`, `PENDING_VERIFICATION`, or a blocking state when exact evidence is required.

If required memory is missing, do not guess project identity rules from general knowledge.

# Phase 1 — Define Content Function

For each asset/frame, state:

```text
WHAT DOES IT SAY?
WHAT SHOULD BE UNDERSTOOD FIRST?
WHAT IS ITS FUNCTION?
WHAT SHOULD THE VIEWER FEEL / DO NEXT?
WHAT IS PROTECTED?
```

Examples of functions:

- question/hook;
- blockage/tension;
- explanation;
- obstacle/example;
- shift/reframe;
- agency/definition;
- expansion/conclusion;
- CTA;
- Story interaction.

Do not choose typography or composition before the content function is understood.

# Phase 2 — Resolve Canonical Assets

When identity or reusable assets are involved, resolve them through:

`knowledge/project/EBL_asset_registry.json`

Chosen logo:

`EBL-ASSET-LOGO-001 — Geometric Reader Integrated Logo`

Rule:

```text
CANONICAL ASSET EXISTS
→ USE EXACT APPROVED ASSET / APPROVED VARIANT
→ DO NOT REGENERATE A SIMILAR SUBSTITUTE
```

If the exact binary is required but not verified/resolvable, stop with:

`CANONICAL_ASSET_UNRESOLVED`

A written description is memory, not a replacement for a canonical binary.

# Phase 3 — Choose Platform Structure

## Feed / carousel

Use approved feed dimensions.

For multi-slide work:

- map narrative progression;
- give each slide a role;
- preserve shared visual grammar;
- allow meaningful variation;
- keep numbering / logo behavior systematic.

## Story

Use:

`1080 × 1920 px` — `9:16`

Retrieve:

`knowledge/project/EBL_story_template_rules.md`

Story must not be a stretched feed post.

Reserve:

- top-safe entry;
- main message zone;
- secondary copy zone;
- interaction/sticker zone;
- brand-signature zone;
- bottom-safe/CTA support.

Keep reusable clean template separate from Instagram UI mockup.

Current Story template asset:

`EBL-ASSET-STORY-TPL-001 = REVIEW_CANDIDATE`

Its exact composition is not a permanent approved master until the human explicitly approves it.

# Phase 4 — Apply EBL Visual Grammar

Use the approved family:

- warm ivory/paper ground;
- rust/burnt orange;
- ochre/mustard;
- deep navy / muted green / olive;
- charcoal/black;
- asymmetry;
- negative space;
- painterly/material texture;
- hand-drawn lines;
- circles, arches, grids, dots, signs;
- meaningful irregular fields.

Avoid generic language-school / infographic / stock-corporate drift.

## Klee-informed behavior

Use principles, not copied artwork:

```text
VISIBLE ↔ LEGIBLE
LINE AS PATH
SIGN AS MEANING-BEARING FORM
READING-LIKE SEQUENCE
DRAWING + PAINTING
CONTROLLED INCOMPLETENESS
```

Ask what each line/form/color field **does** before including it.

---

# Phase 5 — Apply Semantic Typography

Use:

```text
MEANING
→ FUNCTION
→ READING ORDER
→ FONT ROLE
→ WEIGHT / SIZE
→ ALIGNMENT
→ LINE BREAKS
→ SPACING
→ EMPHASIS
```

Current EBL grammar:

- editorial serif: conceptual / reflective / cultural / thesis / major question;
- sans serif: direct / practical / operational / explanatory.

This is not rigid; it is meaning-driven.

Do not use color emphasis decoratively. Emphasize only the words/ideas whose meaning requires it.

If raster type is damaged, use source-based native reconstruction rather than repeated recoloring.

---

# Phase 6 — Apply Chosen Logo

Chosen logo:

`EBL-ASSET-LOGO-001`

Use:

- verified primary supplied master; or
- an explicitly approved child/application asset.

Never regenerate a similar logo.

Check:

- geometry fidelity;
- integrated logo typography;
- scale;
- anchor logic;
- optical clear-space;
- visual secondary role;
- no extra support objects.

When replacing old branding:

```text
REMOVE
→ REPAIR
→ 100% INSPECTION
→ NORMAL-SIZE INSPECTION
→ PLACE APPROVED LOGO
```

---

# Phase 7 — Generate / Build Candidate

Produce a candidate from the approved content/function map.

Keep:

- content meaning locked;
- public name correct;
- logo correct;
- platform role correct;
- visual identity correct.

Candidate state:

`REVIEW_CANDIDATE`

Not final.

Record which:

- decision IDs;
- asset IDs;
- example IDs;
- source artifacts

were used.

---

# Phase 8 — Human-Directed Revision

Use:

```text
HUMAN = WHAT CHANGES
REFERENCE = HOW IT SHOULD CHANGE
AI = EXECUTES THE REQUESTED CHANGE
```

Revision isolation:

```text
AUTHORIZED AREA = EDIT
EVERYTHING ELSE = PRESERVE
```

Before correction, check `EBL_failure_memory.md` for known patterns relevant to the requested area.

Capture reusable learning separately from one-off corrections.

---

# Phase 9 — Run Memory Compliance QC

Mandatory first QC gate:

`qc/QC-EBL-MEM-001_memory_compliance_qc.md`

Verify:

- correct memory registry loaded;
- task-specific retrieval map followed;
- current human instruction has priority;
- newest non-superseded decisions used;
- canonical asset state respected;
- no missing metadata invented;
- candidate vs approved state preserved;
- relevant failure memory checked;
- memory trace recorded.

Required result before final project QC:

`PASS_MEMORY_COMPLIANCE`

or an explicitly documented non-blocking unknown.

---

# Phase 10 — Run EBL Project QC

Mandatory project gate:

`qc/QC-EBL-001_project_master_qc.md`

Run relevant specialized modules too:

- logo QC;
- typography QC;
- profile QC;
- Instagram visual/audience QC;
- Story QC;
- artifact inspection.

Use approved/rejected calibration in `EBL_visual_examples.md` when relevant.

A known active failure from `EBL_failure_memory.md` cannot be averaged away by a high aesthetic score.

---

# Phase 11 — Creative AI Final Edit

Retrieve final-AI system learning.

Classify each asset:

```text
P0 PRESERVE
P1 CLEANUP
P2 MICRO-REFINE
P3 SOURCE-BASED RECONSTRUCTION
P4 CONCEPTUAL CHANGE — HUMAN AUTHORIZATION REQUIRED
```

Use:

```text
FINAL QUALITY = MAXIMUM COHERENCE
                WITH
                MINIMUM NECESSARY CHANGE
```

No-change / preserve may be the correct final creative decision.

---

# Phase 12 — AI Creative Synthesis + Heavy QC

Evaluate the complete set / asset holistically.

Check:

- memory compliance;
- content fidelity;
- meaning-to-form;
- typography;
- logo;
- EBL identity;
- painterly integrity;
- sequence/system consistency;
- platform readability;
- audience relevance;
- active failure memory;
- artifacts;
- native-size quality;
- realistic feed/Story-size quality;
- master/derivative architecture.

On mandatory failure:

```text
ROOT CAUSE
→ SMALLEST SAFE FIX
→ RERUN FAILED GATE
→ RERUN MEMORY COMPLIANCE IF MEMORY/ASSET STATE CHANGED
→ RERUN GLOBAL COHERENCE
```

Do not redesign unaffected assets.

AI result may be:

`PASS_FOR_HUMAN_FINAL_REVIEW`

not automatic final approval.

---

# Phase 13 — Human Final Approval

Only explicit human approval promotes the asset to:

`FINAL_PUBLISHING_MASTER`

Record the approval state.

If human approval changes a durable decision or asset state, update the decision/asset registries before the next production run.

---

# Phase 14 — Output Architecture

Keep separate:

```text
ARCHIVAL / PROJECT MASTER
≠
PLATFORM DERIVATIVE
```

Do not repeatedly resize the working master.

After approval create platform outputs once from the final master.

QC evidence should include as relevant:

- memory-compliance trace;
- full-set contact sheet;
- native-resolution critical-area sheet;
- realistic platform-size preview;
- logo close-up;
- typography close-up;
- repair-region close-up;
- Heavy QC report;
- unresolved-risk record.

---

# Phase 15 — Learn / Structuralize / Promote

When the human asks to learn, structuralize, refine or remember:

```text
OBSERVATION
→ CLASSIFY
→ RECORD DECISION / FAILURE / EXAMPLE / ASSET STATE
→ UPDATE QC IF TESTABLE
→ UPDATE MEMORY REGISTRY IF NEW MEMORY OBJECT EXISTS
→ UPDATE RETRIEVAL MAP IF FUTURE TASKS MUST LOAD IT
→ CHECK FOR DUPLICATE / CONFLICTING ACTIVE RULES
```

Classify the learning:

```text
ONE_OFF_CORRECTION
CONTENT_SPECIFIC_DECISION
REUSABLE_EBL_PROJECT_RULE
CROSS_PROJECT_SYSTEM_RULE
```

Update:

- `EBL_decision_log.md` for durable decisions and rationale;
- `EBL_failure_memory.md` for negative memory;
- `EBL_visual_examples.md` for calibration;
- `EBL_asset_registry.json` for identity/asset states;
- `EBL_project_memory.md` for durable project synthesis;
- system workflow knowledge only when the lesson is truly cross-project and promotion is authorized.

A learning task is incomplete if the new information is documented but cannot be retrieved or tested by QC.
