# FINAL-AI-001 — Creative AI Final Edit

## Purpose

Perform a controlled late-stage creative refinement after the design, content, branding, and normal QC have already been substantially finalized.

This stage improves **how the approved idea is expressed**. It does not invent a different idea.

## Core Principle

```text
APPROVED MEANING = LOCKED
APPROVED BRAND IDENTITY = LOCKED
MAJOR VISUAL CONCEPT = LOCKED

TYPOGRAPHIC / SPATIAL / OPTICAL FINISHING = REFINABLE
```

Creative AI Final Edit is **semantic + visual finishing**, not unrestricted redesign.

A final-edit stage does not create an obligation to change the asset.

```text
STRONG APPROVED FORM + NO MEANINGFUL FAILURE = PRESERVE
```

## Semantic Analysis First

Before editing, state the communication function of each frame.

For each slide/card, determine:

```text
WHAT DOES THE SLIDE SAY?
WHAT SHOULD THE VIEWER UNDERSTAND FIRST?
WHAT EMOTION / COGNITIVE STATE SHOULD IT CREATE?
WHAT IS THE SLIDE'S ROLE IN THE SEQUENCE?
WHAT MUST REMAIN UNCHANGED?
```

Do not make font, alignment, spacing, or composition decisions before this analysis.

For a multi-asset set, complete the whole-work read before editing any single asset.

---

## Preserve / Intervene Classification — mandatory

Classify every asset before editing.

```text
P0 PRESERVE
P1 CLEANUP
P2 MICRO-REFINE
P3 SOURCE-BASED RECONSTRUCTION
P4 CONCEPTUAL CHANGE — HUMAN AUTHORIZATION REQUIRED
```

### P0 — Preserve

Use when the asset already performs its semantic, visual, brand, and platform role.

Action:

- make no creative change;
- record preservation explicitly;
- continue through QC.

### P1 — Cleanup

Correct accidental production defects only.

### P2 — Micro-refine

Make controlled typography / hierarchy / spacing / alignment / optical refinements without changing approved meaning or identity.

### P3 — Source-based reconstruction

Return to a cleaner approved source when local raster repair would preserve or compound damage.

Follow the clean-source hierarchy in `final_ai_closed_loop_production.md`.

### P4 — Conceptual change

Any change to approved wording, narrative order, identity, major composition concept, or logo geometry requires explicit human authorization before execution.

## Allowed Creative Refinements

When supported by meaning, project style, and approved scope, AI may refine:

- font choice within the approved typography direction;
- serif / sans role assignment;
- font weight;
- text size;
- tracking;
- leading;
- line breaks;
- text-box width;
- alignment;
- text-to-image relationship;
- hierarchy between title, support, definition, question, CTA, and metadata;
- negative space;
- optical spacing;
- focal-point strength;
- local contrast;
- color emphasis where the approved meaning allows it;
- line / shape relationship to semantic function;
- painterly integration;
- visual rhythm between slides;
- minor texture continuity / artifact cleanup;
- optical balance.

All changes must be explainable through:

```text
MEANING
+
SLIDE FUNCTION
+
PROJECT VISUAL SYSTEM
+
SOURCE-SUPPORTED DESIGN PRINCIPLES
```

If the explanation is weak and the current form already performs correctly, preserve it.

## Protected Elements

Do not independently change:

- approved wording;
- factual meaning;
- client claims;
- CTA meaning;
- number of approved supporting points;
- narrative order;
- approved logo master;
- public brand name;
- approved identity rules;
- major illustration concept;
- named-style source into literal copying;
- legal / platform facts.

Any change to a protected element requires explicit human authorization.

## Clean-Source Rule — mandatory for damaged derivatives

If a raster area is degraded, do not default to repeated repair of the damaged derivative.

Use:

```text
EDITABLE / LIVE SOURCE
→ CLEAN APPROVED MASTER
→ APPROVED TEXTLESS / ELEMENT-FREE MASTER
→ CLEAN REGION FROM SAME ARTWORK
→ TARGETED LOCAL REPAIR
→ GENERATIVE RECONSTRUCTION LAST
```

Do not patch around a defect when a cleaner approved source can reconstruct the same area more faithfully.

---

## Defect Precedence

Resolve final-stage problems in this order:

```text
1. CONTENT / FACTUAL FIDELITY
2. APPROVED MASTER / IDENTITY FIDELITY
3. TYPOGRAPHY / LOGO READABILITY
4. ARTIFACT / RASTER INTEGRITY
5. SYSTEM / CAROUSEL CONSISTENCY
6. PLATFORM READABILITY
7. OPTIONAL AESTHETIC POLISH
```

Do not beautify around an unresolved mandatory failure.

## Reference-Informed Creative Reasoning

Use `creative_synthesis_sources.md` as evidence for creative questions.

### Layout / hierarchy

Ask:

- what is the single primary focal point?
- what is second and third in the reading order?
- is related content grouped?
- is alignment reinforcing the meaning?
- is negative space creating useful separation / pacing?
- are repeated system elements producing coherence without mechanical repetition?

### Typography

Ask:

- is the type serving the reading experience?
- does hierarchy follow semantic importance?
- does spacing support readability?
- does font character support tone without distracting from meaning?
- is the text optically solid at native size?

### Painterly / Klee-derived visual behavior

Ask:

- what job does each significant line perform?
- should line character change because the subject/function changes?
- can line and color create controlled tension rather than perfect matching?
- can a simple form reward a secondary reading without obscuring the first?

Do not turn these questions into mandatory visual clichés.

---

## Carousel Semantic Refinement

A carousel must be reviewed as a sequence.

For every transition `n → n+1`, check:

- semantic continuity;
- visual continuity;
- variation;
- pacing;
- whether the next slide advances the argument;
- whether the previous slide creates a reason to continue.

Consistency means **shared grammar**, not identical composition.

Repeated system elements should preserve role, format, anchor logic, hierarchy, and family resemblance. Local contrast adaptation may be allowed when function requires it and the project rule does not require fixed color treatment.

## EBL Post 01 Semantic Map

When used for Post 01:

```text
01 QUESTION
02 BLOCKAGE
03 OBSTACLES
04 SHIFT IN PERSPECTIVE
05 AGENCY
06 EXPANSION
```

Creative refinement should reinforce these differences.

Examples:

- QUESTION: immediate focal question, strong stopping power, selective emphasis;
- BLOCKAGE: controlled tension / interruption, without sacrificing readability;
- OBSTACLES: multiple situations organized without infographic-style flattening;
- SHIFT: old question versus new question must be visibly reoriented;
- AGENCY: stable, confident definition and exactly two supports;
- EXPANSION: more breathing room and concluding visual release.

These are semantic directions, not permission to change approved copy.

## Execution Sequence

```text
1. RETRIEVE CONTEXT + SYSTEM LEARNINGS
2. SOURCE LOCK
3. LOCK PROTECTED ELEMENTS
4. ANALYZE WHOLE WORK / SLIDE FUNCTIONS
5. CLASSIFY EACH ASSET P0–P4
6. DIAGNOSE WEAKNESS
7. CHOOSE CLEANEST VALID SOURCE
8. PROPOSE MINIMAL HIGH-VALUE REFINEMENTS
9. APPLY REFINEMENTS ONLY WHERE JUSTIFIED
10. RUN NATIVE TYPOGRAPHY / ARTIFACT CHECK
11. RUN LOGO / BRAND CHECK
12. REVIEW FULL CAROUSEL RHYTHM
13. COMPLETE DELTA RECORD
14. HAND OFF TO FINAL-AI-002
```

## Required Output

- applied-change record;

- QC handoff notes;

FINAL-AI-001 cannot declare a publishing master.
