# A Word — Learned Visual-System Process

This document records the process used to analyze references, extract the reusable template, build the HTML visual system, check the rendered result, and convert discoveries into canonical project rules.

## 1. Naming Separation

Maintain two names with different jobs:

- **Recall/internal name:** `A Word`
- **Public title:** **A Word from the World**

The recall name is used to retrieve the project system. The public title is the exact wording shown on Posts and Stories.

## 2. Lock the Parent Brand

Before designing a piece, preserve:

- English Beyond Language identity
- official EBL logo
- core palette
- typography roles
- visual principle: **Structured underneath, alive on the surface.**
- approximate balance: **70% editorial clarity / 30% artistic texture**

Do not redesign the brand for each piece.

## 3. Analyze the Approved Reference

Do not begin by inventing a new layout. Analyze the approved reference first.

### A. Macro composition

Identify major functional zones:

- brand / header
- main text / quote
- attribution / source
- image / artwork
- geometric framing

### B. Hierarchy

Determine what the viewer notices first, second, and third.

For A Word:

1. quote / highlighted words
2. remaining quote
3. image
4. logo
5. series title
6. attribution
7. decorative geometry

### C. Typography

Analyze:

- font role
- scale
- alignment
- line breaks
- leading
- emphasis behavior
- attribution hierarchy

### D. Logo behavior

Analyze:

- scale relative to page
- placement
- clear space
- integration with geometry

### E. Geometry

Analyze:

- asymmetry
- edge-entry behavior
- density by zone
- rules, dots, circles, arcs, blocks
- relationship to image

### F. Image treatment

Analyze:

- crop
- tonal treatment
- monochrome/sepia behavior
- contrast
- whether image is hard-edged or fades into background
- whether geometry overlaps the image

### G. Texture

Analyze tactile behavior across:

- background
- geometry
- image

## 4. Separate Fixed vs Variable

Every analyzed feature must be classified.

### Fixed

Features required for project recognition and consistency.

Examples:

- public title
- logo
- typography roles
- palette
- quote-first hierarchy
- geometric DNA
- image field logic
- source-fidelity rule

### Variable

Features that adapt to each source.

Examples:

- exact quote
- highlighted words
- attribution
- image/artwork
- crop
- mood
- source-specific reference

Do not convert a one-off creative decision into a permanent rule without explicit approval.

## 5. Extract the Reusable Template

Convert the reference analysis into a structural grammar.

### Story flow

**Series Header → Main Quote/Text → Attribution/Source → Image/Artwork**

### Post flow

**Series Header → Main Quote/Text → Attribution/Source → Image/Artwork**

The quote/text leads; the image supports meaning.

## 6. Build the Visual-System Prototype

Create a shareable HTML guideline that documents and demonstrates:

- naming
- core principle
- palette
- typography
- logo behavior
- quote treatment
- geometric language
- image treatment
- fixed vs variable rules
- Story/Post structures
- QC

Prefer live HTML/CSS structural demonstrations over outdated raster examples when possible.

## 7. Render Check

Never assume the HTML structure works because the code is logically correct.

Inspect the rendered result for:

- overlapping text
- incorrect scale
- responsive failure
- poor spacing
- wrong public title
- outdated reference images
- hierarchy problems

The rendered output is part of the test.

## 8. Targeted Correction

Correct failed elements rather than redesigning the whole system.

Examples:

- simplify preview copy if it overlaps
- adjust type scale
- change attribution position
- improve responsive rules
- remove outdated raster references containing retired titles
- rebuild previews as live CSS structures

## 9. QC

Canonical QC checks:

1. Correct EBL logo used.
2. Overall result feels editorial, cultural, and recognizably EBL.
3. Quote is visually dominant.
4. Exact source text is preserved.
5. Attribution is accurate.
6. Burnt-orange emphasis is selective.
7. Image supports meaning.
8. Image fades naturally into dark field where required.
9. Geometry frames rather than distracts.
10. Texture stays subtle.
11. Readability remains strong.
12. Public title reads exactly **A Word from the World**.

## 10. Human Approval

The user approves the canonical result.

Only approved reusable discoveries are promoted to fixed project rules.

## 11. Learning Review

At the end of a cycle, record:

- what improved consistency
- what repeatedly failed
- which rules should become permanent
- which decisions were source-specific only

## 12. Change Control

- Permanent rule: `Update "A Word" Project: ...`
- Temporary exception: `For this one only: ...`

Temporary changes never overwrite the canonical project system automatically.

## Process Summary

**Reference → Visual Analysis → Fixed/Variable Split → Template Extraction → HTML Prototype → Render Check → Targeted Correction → QC → Human Approval → Learning Review**
